# ArcGIS Pro MCP Bridge

ArcGIS Pro MCP Bridge connects MCP-capable AI agents to a live ArcGIS Pro
session through a local ArcGIS Pro add-in and a local MCP server.

Use it when you want an agent to inspect maps, layers, layouts, legends, project
state, visual previews, exports, geoprocessing calls, and guarded ArcPy script
runs without giving the agent unrestricted access to ArcGIS Pro.

## What It Includes

- `ArcGisProBridgeAddIn/` - ArcGIS Pro add-in that runs inside ArcGIS Pro.
- `ArcGisProMcpServer/` - MCP stdio server that exposes ArcGIS Pro tools.
- `ArcGisProBridgeContracts/` - shared request/response contracts.
- `scripts/` - helper scripts for publishing the server and packaging the add-in.
- `arcgis-pro-mcp.config.json` - conservative default bridge configuration.
- `.mcp.json` - development MCP client config that runs the server from source.
- `docs/arcpy-mapmaking-guide.md` - optional ArcPy map-making guidance for agents.

## Features

- Project, map, layer, layout, and object-registry inspection.
- Active-view, active-map, and layout-preview image export.
- Guarded layer, map, layout, legend, export, and project-save operations.
- Guarded ArcGIS Pro geoprocessing execution.
- Guarded ArcPy script execution through the open ArcGIS Pro session.
- Dry-run support and confirmation flags for higher-risk actions.
- Optional allowed-root, artifact-directory, timeout, tool-group, and audit-log
  configuration.

## Requirements

- Windows.
- ArcGIS Pro 3.x.
- .NET 8 SDK.
- PowerShell.
- Visual Studio with the ArcGIS Pro SDK for the normal add-in build workflow.

The MCP server can be built with the .NET CLI. The ArcGIS Pro add-in can be
compiled with the .NET CLI, but normal Esri add-in packaging is best done with
Visual Studio and the ArcGIS Pro SDK. A PowerShell fallback packaging script is
included.

## Quick Start

Build the solution:

```powershell
dotnet build ArcGISProMcpBridge.sln
```

Publish the MCP server:

```powershell
.\scripts\publish-server.ps1 -Configuration Release
```

Package and register the ArcGIS Pro add-in:

```powershell
.\scripts\package-addin.ps1 -Configuration Debug
```

Restart ArcGIS Pro after installing the add-in.

## Run During Development

Run the MCP server from source:

```powershell
dotnet run --project ArcGisProMcpServer/ArcGisProMcpServer.csproj
```

For development clients, point your MCP client at `.mcp.json`.

For installed use, point your MCP client at the executable generated by:

```powershell
.\scripts\publish-server.ps1 -Configuration Release
```

The publish script writes generated output under `publish/`, which is ignored by
git because it is machine-specific.

## Configuration

The bridge reads configuration from the first available location:

1. `ARCGIS_PRO_MCP_CONFIG`
2. `arcgis-pro-mcp.config.json` in the current working directory
3. `arcgis-pro-mcp.config.json` beside the published server executable
4. `%LOCALAPPDATA%\ArcGISProMcpBridge\config.json`

The included config uses conservative defaults:

- destructive geoprocessing is disabled by default
- feature edits are disabled by default
- save, overwrite, destructive geoprocessing, and script execution actions
  require explicit confirmation flags
- timeouts and enabled tool groups are configurable

## MCP Client Example

After publishing the server, configure your MCP client with the generated
executable and config path:

```json
{
  "mcpServers": {
    "arcgis-pro": {
      "type": "stdio",
      "command": "C:\\path\\to\\ArcGisProMcpServer.exe",
      "args": [],
      "env": {
        "ARCGIS_PRO_MCP_CONFIG": "C:\\path\\to\\arcgis-pro-mcp.config.json"
      }
    }
  }
}
```

For development, use `.mcp.json` from the repository root.

## Agent Prompt

After the MCP server is configured and ArcGIS Pro is open with the add-in
loaded, give your agent a prompt like this:

```text
You have access to the ArcGIS Pro MCP Bridge. Use it to inspect the current
ArcGIS Pro project before making changes. Prefer dry-run operations first for
map, layer, layout, legend, export, geoprocessing, project-save, and ArcPy
script actions. Use stable object IDs returned by the read tools when editing
maps, layers, layouts, legends, and map frames. Preview layouts or active maps
after visual changes, critique the result, and iterate only as needed. Do not
run destructive geoprocessing, overwrite files, save projects, or execute ArcPy
scripts unless I explicitly confirm that action. When writing ArcPy map-making
or layout/export automation, consult docs/arcpy-mapmaking-guide.md first.
```

## Smoke Test

1. Build the solution.
2. Package and register the add-in.
3. Restart ArcGIS Pro.
4. Start or publish the MCP server.
5. Call `pro.ping`; it should return `pong` without needing ArcGIS Pro.
6. Open ArcGIS Pro with the add-in loaded.
7. Call `pro.health`; it should return bridge and project status.
8. Call `project.get_current`, `map.list`, `layer.list`, or `layout.list`.
9. Call `visual.capture_active_view` or `visual.export_layout_preview` to verify
   image artifact output.

## Safety Model

The bridge is designed for local use with an active ArcGIS Pro session. It
supports dry runs, stable object IDs, configurable allowed roots, confirmation
flags, disabled destructive operations by default, and optional audit logging.

Review tool calls before allowing saves, overwrites, destructive geoprocessing,
or ArcPy script execution.
